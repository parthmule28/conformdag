# P2 Design System And UI Surface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan task-by-task. Each task uses strict red -> green -> refactor TDD, a fresh implementer, an independent reviewer, and a fix/re-review loop before the next task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the P1 platform shell into a complete, URL-addressable governance product without weakening the single scan pipeline, authoritative pack validation, baseline semantics, or incomplete-report contract.

**Architecture:** Keep `scan_repository()` as the only evaluator. Add additive platform read contracts over persisted `ScanRow` and `FindingRow` data, keep policy packs and quality gates in YAML, and keep baselines and suppressions in the platform database. Expose explicit backend wire DTOs through `/api/v1`; the SPA consumes only the hand-written TypeScript client. Split the current `App.tsx` into a tokenized shell, router, query/client layer, shared primitives, and route pages. Use a disposable SQLite-backed platform process for real browser journeys.

**Tech Stack:** Python 3.12, Pydantic, FastAPI, SQLAlchemy/Alembic, PostgreSQL/SQLite, ruamel.yaml, React 19, Vite, TypeScript strict, Tailwind v4, TanStack Query, React Router, Vitest, Playwright, pytest, Ruff, Pyright, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-17-p2-ui-design.md`

## Global Constraints

- Preserve `scan_repository()` as the sole evaluation pipeline. Aggregates, filters, and UI summaries query persisted rows and never evaluate policy code.
- Use strict TDD. Every production behavior starts with a focused test that fails for the intended reason before implementation.
- Every pack mutation reconstructs and validates the complete pack with `validate_policy_pack()` before `_write_pack()`. Rejection must leave source bytes unchanged.
- Keep YAML as the source of truth for policies and quality gates. Keep baseline selection in `RepositoryRow`; do not duplicate either state in browser storage.
- An unsuppressed `FindingStatus.ERROR` remains an incomplete report with a fatal `EVALUATION_ERROR` and `gate_result: null`. An active platform suppression may waive the corresponding error; an expired one may not.
- A baseline must be same-repository, `status == "succeeded"`, and `complete is True`.
- Startup schema work remains Alembic-owned. The only P2 schema migration adds nullable finding `end_line`; no runner migration and no `Base.metadata.create_all()`.
- Register every new FastAPI route before `/api/{rest:path}` and the `/` `StaticFiles` mount. The fallback must continue to return JSON 404 responses for every unknown API method, including `PUT`.
- Python remains Pyright-strict with zero errors and at least 90% coverage. Use targeted `pyright: ignore[...]` only where the repository already permits it. TypeScript remains strict with no unused symbols.
- Preserve the existing Hatch artifact rule for `src/conformdag/platform/static/**`.
- Do not add semantic/BYOK configuration, scheduled scans, webhooks, realtime transport, identity systems, OpenAPI redesign, dbt packs, MCP, report diffing, or broad scan-engine refactoring.
- Do not push, merge, publish, create a release tag, or modify OpenCode configuration.
- Before the first implementation task, search the configured OpenCode/native and repository-local skill catalogs for frontend design, API contract-first, Playwright, accessibility, and testing skills. Load every matching skill before its governed task and record unavailable skills explicitly in the P2 SDD ledger.

## Contract-First Record

Create `.superpowers/sdd/2026-09-17-p2-ui/progress.md` before implementation. Record the skill preflight, route contracts, and task evidence there. The route contract must list method, path, parameters, request body, response shape, error statuses, authentication requirement, ordering, and pagination behavior before the frontend client consumes a new route.

The backend wire contract is independent of React. Backend handlers return explicit DTOs from `src/conformdag/platform/contracts.py`; they do not return SQLAlchemy rows. The frontend imports only TypeScript types and client functions. Focused client tests use stable JSON fixtures and mocked transport; Playwright uses the real HTTP API and never replaces backend tests with network mocks.
