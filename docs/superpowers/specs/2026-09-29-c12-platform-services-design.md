# C12 — Extract reusable platform services

## Intent and scope

Give repository, scan, baseline, and suppression reads and mutations one reusable owner, callable by a future CLI or MCP adapter without HTTP objects. FastAPI remains the transport adapter. Preserve the existing API paths, auth, request validation, response shapes, statuses, error details, headers, exports, scan lifecycle, and persistence schema. Base this slice on `origin/main@6684bc2`, where C10 and C11 are accepted.

## Ownership and interfaces

Create `src/conformdag/platform/services/{__init__,repositories,scans,baselines,suppressions}.py`. Platform services own repository, scan, baseline, and suppression read/mutation semantics, including SQL construction, persistence eligibility checks, and domain-specific mutations. FastAPI routes own HTTP binding and projection only. `__init__.py` exports one shared `ServiceError` vocabulary: `NotFoundError`, `ConflictError`, and `InvalidOperationError`. Errors carry stable details but no HTTP status or FastAPI types. Services do not import FastAPI, `Request`, `Response`, `HTTPException`, Typer, or transport auth.

Services accept `Session` and primitives or service-owned typed inputs, never route request models or dependencies. Results may be detached domain/contract-ready values, service result dataclasses, or a canonical `ScanReport`; do not require a live session after the route's `with` block to serialize them. A paginated result includes items and the filtered total. The route sets `X-Total-Count`, serializes response contracts, maps service errors, and creates HTTP responses. Keep route registration and physical routes in `app.py` until C13. Do not create a generic service base class.

## Repository and aggregate flow

`repositories.py` owns registration, listing, and repository existence checks. For direct registration, resolve paths, require an existing directory and optional existing policy-pack file, enforce the existing repository-name rule (`^[a-z0-9][a-z0-9._-]*$`), check duplicate names, persist normalized paths and the supplied Airflow profile, and invoke the existing platform profile coercion/validation independently of HTTP validation. The route still applies existing Pydantic name, field-length, and profile validation before calling the service; direct service callers cannot bypass name or domain validity. Catch an identifiable uniqueness constraint on `flush()` and raise `ConflictError`; avoid translating unrelated database failures into conflicts. Preserve the established 422 path errors and 409 duplicate detail at the HTTP boundary.

Workspace file loading and pack registration remain orchestration in `app.py`/existing workspace components, but its repository persistence uses repository service operations, preserving skip-existing-name counts and behavior. Workspace models already validate repository names and profiles; `load_workspace()` resolves relative paths and checks existence, but does **not** require a registered repository path to be a directory or its policy-pack path to be a file. Preserve that existing workspace path-kind behavior: do not silently run direct-registration `is_dir()`/`is_file()` checks on workspace-loaded entries. Give repository-service persistence an explicit workspace-registration operation/input for already workspace-validated paths; it owns duplicate skipping and insertion without bypassing name/profile validity for direct callers. Review `overview` and `repository_trends`: aggregate query/calculation stays in `platform.aggregates`; move route-level repository existence and session/business orchestration into the repository service or a small service wrapper so no route owns SQL semantics. Keep response contracts and date-window behavior unchanged.

## Scan, baseline, and suppression flow

`scans.py` owns queueing with dashboard trigger and queued status, cancellation, status, history, stored-report loading, and findings queries/projection data. Preserve history ordering (`created_at DESC`, `id DESC`), finding filter normalization, baseline-status semantics, finding ordering, pagination, and pre-pagination totals. A missing baseline or ineligible baseline yields `None` status, not an implicit existing finding; either baseline-status filter then yields zero matches. `export_scan()` obtains the canonical stored report from the scan service, while `app.py` chooses JSON/SARIF/HTML, media type, and `Response`; export bytes do not change. An absent scan and an absent artifact may be distinct internal errors, but both must retain the existing HTTP 404 `scan report not available` behavior for stored-report routes. No outcome reclassification or report/gate/finding semantic changes.

`baselines.py` owns setting and reading any baseline state needed by the four domains. It requires an existing repository, a scan belonging to it, and existing `eligible_baseline()` eligibility (`SUCCEEDED` and `complete=True`); preserve current 404 and 409 details and same-repository restriction. `suppressions.py` owns list/create/update, chronological order, `(policy_id, fingerprint)` uniqueness, audit fields, `source="platform"`, expiry, and current partial-update semantics. Translate only identifiable uniqueness failures to `ConflictError`. Do not change suppression application in the runner or application workflow.

## Errors, transactions, and lifecycle

Routes keep the existing admin dependency and 401/503 behavior on mutations, plus all current Pydantic/query validation. They translate typed service errors to the established HTTP status and detail per operation; a generic error class does not impose one global mapping that changes historical endpoint behavior. Preserve missing repository/scan, cancellation conflict, baseline ineligibility, suppression conflict, unavailable report, and invalid path details.

The caller opens the `Session`, commits ordinary multi-step mutations on success, and rolls back on error. Services may `flush()` to surface database constraints inside their domain boundary, but do not commit. On failed flush, the caller must roll back before reusing the session; service errors may wrap identifiable integrity failures without masking unrelated database errors. Existing atomic typed transition primitives retain their own commit/rollback ownership for fencing: cancellation calls `transition_scan_to_cancelled()`, never an ordinary ORM status assignment. Preserve queued/running/terminal and trigger values. No Alembic migrations, worker/runner orchestration changes, or new scan pipeline.

Add a workspace-loading compatibility characterization against the current route/loader before extracting persistence. Establish red service tests before moving implementation. Add or retain HTTP compatibility tests for exact statuses/details, auth, request validation, headers, response shapes, and export content.
