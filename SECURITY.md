# Security policy

## Supported versions

Security fixes target the latest development branch and the most recent public
beta release once published. Runtime images are independently versioned and
must be reported with their exact tag and digest.

## Reporting a vulnerability

Do not open a public issue for an undisclosed vulnerability. Use GitHub Private
Vulnerability Reporting for this repository when enabled. If it is unavailable,
contact the repository maintainers privately through the security contact shown
in the repository settings.

Include:

- a concise impact description;
- affected commit, release, image, or configuration;
- reproducible steps or a minimal proof of concept;
- any required privileges, network access, or provider configuration; and
- suggested mitigation, if known.

Please avoid including real credentials, private DAGs, personal data, or raw
model prompts and responses. Replace sensitive values with synthetic markers.

We will acknowledge reports, reproduce the issue, coordinate a fix and
disclosure timeline, and credit reporters who want attribution.
